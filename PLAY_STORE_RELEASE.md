# Google Play Release Preparation

## Current Release Status

The project is prepared for a native Android release workflow, but it has **not** been published to Google Play. Publishing requires the developer account owner to provide the final Play Console configuration, signing credentials, production identity, compliance declarations, test participants, and submission approval.

## Personal Developer Account Testing

For personal developer accounts created after 13 November 2023, Google’s current guidance requires a closed test with a minimum of **12 opted-in testers continuously for at least 14 days** before production access can be requested.[1] This project does not claim that the requirement has been met.

## Data Safety and Privacy Draft

The initial MVP is designed to keep conversation history, workspace metadata, routine state, and activity records on the device. When a user sends an AI message in managed mode, the message text and recent bounded conversation context are transmitted to the managed server-side model service to generate a response. The production owner must review the deployed service, hosting logs, all enabled SDKs, and the final data flow before selecting Data safety answers. Google requires developers to make complete and accurate declarations, including data handled by third-party SDKs.[2]

The optional system text-to-speech feature processes answer text through the device’s text-to-speech capability. The release should not request optional contacts, location, camera, or persistent background permissions unless those features are actually implemented, tested, disclosed, and justified.

## Android Build Notes

The current Expo project is portrait-oriented and has the app package generated by the project scaffold. Before any public submission, update the target Android API level to match Google Play’s then-current requirement, create a signed Android App Bundle through the supported publishing build process, test the exact release candidate, and keep a rollback-ready prior version.
